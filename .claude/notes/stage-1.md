# Этап 1 — каркас (2026-10-12)

## Решения и почему
- **Значения токенов в `theme.ts`, а не в CSS.** Клиент может принести любой цвет бренда; контраст (текст на кнопке, акцент как текст на светлом фоне, акцент на тёмном) считается при сборке. Урок Bilto: золото текстом на белом — 1,8:1. Слишком светлый `brand.ink` (<7:1 с белым) = ошибка сборки.
- **Шрифты всех трёх стилей подключены сразу** (variable, с кириллицей — для `ru`). Браузер качает только используемые; цена — 32 `@font-face`, CSS 12 КБ gzip.
- **Иконки — Lucide целиком** (`lucide-static`, только при сборке): ниша не фиксирована, на услугу подходит любое имя. Неизвестное имя = ошибка сборки.
- **Тексты коллекций в папке языка** (`services/nl/x.json`): одно имя файла в разных папках = перевод одного элемента; `slug` можно переопределить. Отзывы без языка — цитируются как есть.
- **Регион получает страницу только с собственным `body`** — шаблонные городские страницы вредят SEO.
- **Секция без данных скрывается сама** вместе с пунктом меню; фоны чередуются автоматически.
- **Нет reveal в Hero** — скрытый первый экран откладывает LCP.
- **Форма**: заглушка API честно отвечает «не доставлено» → посетитель видит телефон и почту. Без JS — простая страница с контактами.
- **Шапка**: фиксированная высота, только тень при прокрутке; без `backdrop-filter` (иначе мобильное меню `fixed` сжимается до высоты шапки). Картинка-лого не сжимается, текстовое — переносится (на 320 длинное имя выталкивало кнопку меню на 27 px).

## Найдено при проверке
- `--breakpoint-nav: 960px` при встроенных брейкпоинтах в rem → `nav:` правила оказались раньше `sm:` в CSS, 4 шага Werkwijze стояли в 2 колонки на 1440. Исправлено на `60rem`, урок записан в базу.
- Git Bash превращает аргумент `/x` в путь Windows → `shoot.py` принимает страницы без слэша (`home dienst-1`).
- Heredoc в Bash-инструменте съедает `\\` — файлы с обратными слэшами писать через Write.
