# Этап 3 — новый клиент одной командой (2026-10-15)

Формат и решения приняты без отдельного согласования: владелец поручил решать самому.

## Решения и почему
- **`client.json` в корне — единственный источник.** `prebuild`/`predev` раскладывают его в `src/data/*` и коллекции при каждой сборке. Причина: на сервере фермы нет `npm install` и сборок (`integraties/hermes-agents.md`) — агент коммитит только `client.json` и фото, проверяет и собирает Vercel. Без `client.json` шаблон работает на заглушках.
- **Одна схема на всё.** Zod в `src/lib/client-schema.ts` проверяет файл, `client.schema.json` генерируется из неё (`z.toJSONSchema`, `io: 'input'`) перед каждой сборкой, а сгенерированные файлы ещё раз проходят схемы сайта (`schema.ts`). Скрипт без зависимостей дублировал бы проверку и разошёлся бы с ней.
- **Неизвестное = `null` или поля нет; `[ЗАПОЛНИТЬ]` в `client.json` — ошибка.** Пустые необязательные тексты на сайте просто скрываются, поэтому на демо не видно заглушек. Чего не хватает — печатает отчёт `apply-client` («перед запуском» / «можно улучшить»).
- **Форма для LLM**: `home.<lang>` повторяет `content/<lang>.json`, но обязательны только `meta.title/description` и `hero.title`; подписи секций и кнопок берутся из `ui.ts → homeDefaults` / `sections.*.nav` / `cta.quote`. Элементы коллекций: общие поля (id, иконка, фото) + объект на каждый язык; порядок = позиция в массиве. Ключи строгие (`.strict()`): опечатка = ошибка с путём к полю.
- **Фото только путями в репозитории**, без скачивания по URL: ссылки Google-профиля протухают, права надо подтвердить. Источник фото — в `sources`.
- **`email` и `legalName` стали необязательными в фактах.** У ремесленников часто нет публичной почты: без неё показывается только телефон, в privacy — телефон; без юр. названия — торговое. При `launched: true` обязательны юр. название, почта, BTW (BE), домен, `privacy.updated`, `demo: false` — это проверяет и `apply-client`, а `check-placeholders` роняет сборку, если остался `[ЗАПОЛНИТЬ]`.
- **`phoneE164` выводится из `phone`** для BE/NL/FR/LU/DE — меньше полей, где агент может ошибиться.
- **`new-site`**: копирует закоммиченный шаблон (`git ls-files`, без `examples/`, заметок, `PLAN.md`), `CLAUDE.md` шаблона → `CLAUDE.template.md`, свой `CLAUDE.md` из `templates/CLAUDE.client.md`, первый коммит. GitHub — только с `--github` (по умолчанию приватный; `--public`, если коммитит не владелец — урок Vercel Hobby). Vercel — импорт в панели (CLI не установлен), шаги печатаются.
- **TypeScript-скрипты без tsx**: `node --experimental-strip-types` (Node 22.6+; на Vercel Node 24). Импорты между файлами, которые грузит Node, — с расширением `.ts` (`allowImportingTsExtensions` есть в базовом tsconfig Astro). Добавлен `@types/node`, чтобы `astro check` проверял скрипты.

## Найдено при проверке
- Zod 4 запускает `superRefine` только после того, как прошли поля, — ошибки приходят в два захода (сначала форма полей, потом связи: языки, ссылки на услуги, требования запуска, файлы). Для агента это нормально: он исправляет по списку.
- Абсолютный путь к файлу `apply-client` склеивал с корнем — исправлено `path.resolve`.
- Путь к иконкам Lucide искался от рабочей папки — при запуске для другой папки (`new-site`) ломался; теперь от самого скрипта.

## Проверено
- Пример `examples/demo-dakwerker.json` (nl + fr, без почты, без фото): сборка, `astro check` 0 ошибок, 0 `[ЗАПОЛНИТЬ]`; 5 страниц × 4 ширины без переполнения и ошибок JS; секции без данных скрыты, почта нигде не выводится.
- Испорченные копии: лишний ключ, неверный стиль, URL вместо пути, `[ЗАПОЛНИТЬ]`, пропущенный перевод, ссылка на несуществующую услугу, дубль секции, alt без фото, нет файла, неизвестная иконка, `launched` без юр. данных — каждое даёт ошибку с путём, ничего не записывается.
- Шаблон без `client.json` собирается как раньше, счёт `[ЗАПОЛНИТЬ]` печатается (82 в 16 файлах).
- **Не проверено**: доставка формы вживую, `new-site --github`, импорт в Vercel.
