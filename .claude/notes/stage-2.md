# Этап 2 — форма, юридическое, SEO, языки (2026-10-15)

## Решения и почему
- **Один маршрут `[...path].astro` + таблица `src/lib/routes.ts`.** Отдельные `[slug]` и `[region]/[slug]` с языковыми префиксами конфликтовали бы по форме адреса; таблица даёт одно место для адресов, hreflang, переключателя и sitemap, а дубль адреса ловится при сборке.
- **Основной язык в корне, остальные под `/<lang>/`**. Домашняя другого языка — `/fr/` (со слэшем), остальные страницы без слэша. Сегменты URL (`regio`, `privacybeleid`…) — в `ui.ts` по языкам.
- **Из фактов убраны тексты, зависящие от языка**: `responseTime` → `content.contact.responseTime`, `stats` → `content.about.stats`, подпись часов → строится из `ui.days`. Факты теперь без языка.
- **Форма**: «ok» только если хотя бы один канал подтвердил доставку; ни одного канала не настроено → 503 + лог «Lead NOT delivered»; honeypot → притворный успех. Без JS — короткая страница на языке посетителя. Уведомление владельцу — на основном языке сайта. Telegram — простой текст без `parse_mode` (ввод посетителя не ломает разметку), поддержан топик (`TELEGRAM_THREAD_ID`).
- **Секреты через `getSecret` (`astro:env/server`)** — читаются в момент запроса на Vercel, в сборку не попадают.
- **Лимит 5 заявок / 10 мин на IP в памяти** — на Vercel экземпляр функции переиспользуется, но не общий; против бота хватает.
- **Юр. тексты**: privacy + cookie на nl/fr/en/ru, собираются из фактов; список обработчиков — `privacy.processors`, Google Maps — только при `showAddress`. Пока `privacy.updated` = null, на странице «черновик». Условия (algemene voorwaarden) не делаем — договор клиента, выдумывать нельзя.
- **JSON-LD**: тип бизнеса из `schemaType`; поля с `[ЗАПОЛНИТЬ]`/null выбрасываются; `Service` ссылается на бизнес через `@id`; AggregateRating не размечаем (правило методики).
- **sitemap**: без privacy/cookie (по плейбуку), `lastmod` только из `updated` в данных, hreflang-альтернативы при 2+ языках. В robots.txt — только после `launched`.
- **og:image** 1200×630 JPEG генерируется из `ogImage` → фото страницы → фото hero.

## Найдено при проверке
- glob-загрузчик берёт поле `slug` как id записи → запись теряла папку языка и не строилась (`/fr/service-un`, регионы). Исправлено `generateId`; урок в базе.
- Длинный адрес GBA давал скролл 19 px на 320 (урок A&T уже был в базе — надо было применить сразу). `shoot.py` теперь находит и вылезающий текст, не только элементы.
- Нижняя панель с WhatsApp на 320: подписи не помещались → ниже 380 px только иконки.

## Проверено
- nl + fr на временных данных: все страницы строятся, hreflang в обе стороны + x-default, переключатель ведёт на перевод страницы, JSON-LD без заглушек, часы «ma – do».
- 6 страниц × 4 ширины без переполнения и ошибок JS; Lighthouse mobile: главная 96/100/100, privacy 98/100/100 (SEO 66 — только `noindex`).
- API на dev-сервере: invalid → 400, honeypot → ok без отправки, неверный токен Telegram → 502 «не доставлено», без JS — страница с телефоном на fr, 6-й запрос → 429.
- **Не проверено**: реальная доставка (нужны ключи) — сделать на тестовом проекте Vercel до первой ссылки клиенту.
